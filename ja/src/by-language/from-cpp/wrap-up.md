# C++ から Rust へ、ここまで

[ほぼ読めるが、既定が違う](basics.md)で、初期化前の変数を読んでもエラーにならない・数値型が暗黙に変換される・整数のあふれが未定義動作になる、といった C++ の既定をひととおり確認しました。構文の見た目は近いので読むだけなら難しくなく、違いはわずかでした。そのあと、同じ感覚では書けない数か所を一つずつ見てきました。

振り返ると、C++ でプログラマが規律として守っていたことが、Rust ではコンパイラの側に移っていました。Rule of Five を手書きで守る、`std::move` でムーブを明示する、const 正確性を慣習で保つ、データ競合を mutex の使い方で防ぐ。Rust ではそれをすべてコンパイラが検査します。

- [所有権とムーブ](ownership.md) — Rule of Five と `std::move` の手動管理を、コンパイル時の所有権検査に
- [参照と借用](borrowing.md) — ダングリング参照を、ライフタイムでコンパイル時に封じる
- [スマートポインタ](smart-pointers.md) — `unique_ptr`→`Box`、`shared_ptr`→`Rc`/`Arc` として対応が取れる
- [enum と match](enum.md) — バリアントにデータを持たせ、match で漏れなく分岐する
- [nullptr と Option](option.md) — `nullptr` を型で締め出す
- [エラー処理](error.md) — 例外から `Result` と `?` へ、エラーを返り値の型で追う
- [トレイト](trait.md) — 純粋仮想関数と継承から、trait でインタフェースを分離する
- [テンプレートとジェネリクス](generics.md) — トレイト境界で制約を明示するジェネリクスへ
- [演算子オーバーロード](operator-overloading.md) — `operator` キーワードから、トレイトの実装として書く
- [並行性](concurrency.md) — データ競合を、`Send`/`Sync` の型システムで防ぐ
- [C・C++ との相互運用](unsafe.md) — `unsafe` と `extern "C"` で既存の C/C++ 資産を呼ぶ
- [ビルドと依存管理](cargo.md) — CMake/vcpkg の役割を Cargo が一本で担う

これらは別々の機能に見えて、根はつながっています。所有権は、メモリの解放でも、借用の期間でも、スレッド間の共有でも、同じ仕組みとして効いてきます。その規律を、Rust では所有権の一機構がまとめて検査します。コンパイラに弾かれる場面の多くは、その所有権が「今それは安全でない」と教えているだけです。

誰がメモリを持ちいつ解放するか、ポインタが何を指しているか、スタックとヒープのコストの違いやコピーの重さ、テンプレートで型を抽象化する考え方。こうした感覚はそのまま Rust で使えます。特にテンプレートとジェネリクスは構造が近く、トレイト境界はテンプレートの制約を明示的に書いたものに対応します。その上に所有権という一点を重ねると、Rust はもう遠い言語ではありません。
